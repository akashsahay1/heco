# HECO Portal — Full Functional Audit (2026-05-06)

> Multi-role end-to-end audit done with real requests (logged-in sessions, actual AJAX calls) + JS↔controller wiring traces. Three role-walks: **Traveller**, **Admin/HCT**, **Service Provider (HSP)**.
>
> Legend: 🐛 **BUG** (broken/errors/wrong behaviour) · 👻 **DUMMY** (UI exists, does nothing) · ❌ **MISSING** (no implementation) · ⚠️ **POLISH** (works but rough)

---

## 0. Where the project stands

The platform is **substantially built but not customer-ready**. Pages render, auth works, the AI trip-planner works, trip-building + pricing + Razorpay order-creation work, the admin trip-manager itinerary builder works, SP profile/availability work. But there's a **recurring class of silent failures** that would frustrate a real customer:

1. **Dropdown-value vs DB-string drift** — hardcoded `<select>` option values that no longer match the actual column values (experience-type filter, difficulty filter, trip-manager travel-prefs, `'draft'`/`'traveller_exploring'` enum literals, `'HLH'` vs `'hlh'`). This is the single biggest root cause across all three roles. CLAUDE.md already warns about it for `CostCalculatorService`; the warning didn't propagate.
2. **Filter handlers that ignore their params** — at least 6 admin/portal filter dropdowns render options that do nothing because the backend hardcodes the WHERE clause.
3. **Controller↔JS response-shape mismatches** — Impact tab, GST report, region badges, dashboard upcoming-trips — all silently empty because the JS reads a key the controller doesn't return.
4. **Two data-loss landmines** — admin "Recalculate" zeros trip costs when there's no itinerary; flipping a paid trip's status back to `not_confirmed` with one click.
5. **SP funnel is dead end-to-end** — application form posts the wrong AJAX key; approval never communicates credentials; no SP can see their assigned trips; automatic SP-matching is broken by a casing mismatch.
6. **Missing customer features** — no profile photo upload; no "Confirm Trip" affordance; Impact tab non-functional.

**Rough completion estimate:** Traveller ~75% (core works, polish + a few real bugs), Admin ~70% (CRUD works, filters/wiring broken in places, Control Panel half-empty), SP ~40% (UI shells exist, most flows non-functional).

## 3. MEDIUM — visible, not blocking

- 🐛 **Six "filter param ignored" handlers** (the pattern): `get_upcoming_trips` (status+dates), `getProviders` (status), `getProviderApplications` (status), `getExperiencesList` (type, difficulty, status), `getSpPayments` (`trip_search`). All render dropdowns/inputs that do nothing.
- 🐛 **One-way "disable" handlers** — `disable_experience`, `disable_regenerative_project`, `deactivate_hct_user`, `deactivate_system_list_item` only set the flag to `false`. UI buttons that imply a toggle ("enable", eye-icon) can't reverse it. (`toggle_region`/`toggle_currency` do it right.)
- 🐛 **Dashboard "Upcoming Trips (30 days)" widget never populates** — JS never calls `get_upcoming_trips`; card permanently shows "Loading...".
- 🐛 **`cultural_etiquette`** populated in DB, in `$fillable`, never rendered on `experience-detail.blade.php` (only `cultural_context` shown). Same for `what_to_expect`/`sustainability_practices`/`community_impact_notes`/`accessibility_notes` (null in seed data but unwired).
- 🐛 **Region badges never render** on My-Itineraries cards (`trip.regions` vs eager-loaded `tripRegions`) and on the Trips admin list (same).
- 🐛 **Two incompatible guest-journey stores** — server session `guest_trip` (homepage Discover + AI chat + login sync) vs `localStorage.heco_guest_journey` (experience-detail "Add to Journey", read by nobody) → a guest who adds from a detail page loses it on login.
- 🐛 **Guests can add experiences but can't open the Journey tab** — `homepage.blade.php:1537` redirects guests to `/login` on `#tab-journey` click, but `ensureTrip()` lets guests add to a session trip and un-hides `#journeyPanels` they can never view.
- 🐛 **"Assign to HCT" not exposed in the lead detail modal** — backend `update_lead` accepts `assigned_hct_id` but the UI never sends it; re-assigning a lead is impossible from the admin.
- 🐛 **Provider-applications status filter ignored** + **`/providers` status filter ignored** → pending/rejected SPs only reachable from one (also-broken) screen.
- 🐛 **`disable_experience` etc. + missing `public/images/placeholder.png`** → experiences without `card_image` render a broken image (`experiences/index.blade.php:157`).
- 🐛 **Experiences index pagination dead** — JS reads `resp.pagination` but handler returns paginator fields at top level; >20 experiences silently truncated.
- 🐛 **`/providers/{id}` "Trip History"** — JS reads `t.service_type`/`t.trip`, handler returns plain Trip models → "Service Type" column always `-`.
- 🐛 **Traveler payment-history modal trip link** uses `pay.trip.id || pay.trip_id` (string fallback) → broken `/trip-manager/HECO-…` link if `pay.trip` null.
- 👻 **Control Panel is missing most of its promised content** — only Lead Reminders, Support Requests, a few content links, and a (non-functional, no JS handler) AI chat box. The architecture docs say it should manage settings / system lists / AI prompts / activity logs / PDF templates — `get_settings`/`save_settings`, `get_pdf_templates`/`save_pdf_template` handlers exist with no UI; no AI-prompts endpoint or activity-log viewer at all.
- 👻 **Travel Preferences page is orphaned** — `travel-preferences.blade.php` manages 5 `system_lists` types (`accommodation_comfort`, `vehicle_comfort`, `guide_preference`, `travel_pace`, `budget_sensitivity`) that **don't exist in the DB** (`SystemList` types are `service_type/accommodation_category/vehicle_type/activity_type/experience_type/payment_mode`). All 5 sections show "No options yet"; `editTravelPreference($id)` `abort(404)`s for any id. This is the root of the trip-info dropdown mismatch (C6).
- 👻 **Edit-service modal in trip-manager has no SP field** — can't change a service's SP via the edit modal (only on first add); the `change_day_service_provider` handler is effectively unreachable from the itinerary tab.
- 👻 **Wishlist `.btn-add-exp` handler** + **`#clearFilters` handler** + **dashboard AI chat** + **`set_landing_preferences`** + **`get_experience_detail` AJAX key** — all registered/handled but never reachable from the UI.
- 👻 **SpPricing table empty for all 12 SPs, no admin UI to set it** → "Services & Pricing" always shows "HCT will set up your pricing".
- ⚠️ **Payments page traveller-row modal** just re-renders the same 4 numbers — never calls `get_traveller_payment_history`.
- ⚠️ **No "Confirm Trip" / "Lock" affordance** for travellers — confirmation only happens implicitly when a full payment verifies.
- ⚠️ **HCT-user edit form missing** — `update_hct_user` exists, no Edit button/form; also no reactivate-user, no reset-password actions.
- ⚠️ **Reviews untestable with seed data** — 0 completed trips that contain experiences → eligibility gate always fails → review count on cards always 0.
- ⚠️ **0 RegenerativeProjects, 0 PdfTemplates, 0 payments** in seed data → those screens are empty everywhere; Experience form's RP picker is empty.

## 4. LOW / POLISH

- `type="date"` inputs throughout admin (trips ×2, payments, trip-info ×3) and on the traveller profile page — violates the project's "jQuery/Air datepicker, no `type=date`" rule. The rebuilt auth pages follow it; nothing else does.
- Bare `<select>` (no searchable dropdown, no chevron) on: profile (gender/country), SP application (region), all admin list filters. Rule violation.
- No bulk-delete pattern (FA-check-icon + select-all + red Danger button + confirm modal) on any list page — coding-rule violation across experiences/regen-projects/regions/currencies/etc.
- Inline CSS in `homepage.blade.php` (hardcoded `#22c55e`, `#dc2626`), `experience-detail.blade.php:413`, etc. — violates "no inline CSS / use `--heco-primary`".
- `showAlert(resp.success, 'success')` in regions/currencies/(rp) → shows literal "true".
- Bootstrap-icons + hardcoded green/blue on the SP dashboard instead of brand turquoise; "Cultural immersion" badge lowercase-i (`ucfirst` on multi-word); `difficulty-extreme` likely has no CSS class.
- Native `alert()`/`confirm()` instead of the SweetAlert helpers in `#btnPayNow`, my-itineraries erase.
- Editing a trip name / group size / travel-pref dropdown fires a synthetic `sendAiMessage('I want to change my …')` to the (rate-limited) AI chat purely "for confirmation" even though the value is also saved directly — fills the chat with "AI assistant is busy" noise.
- `landing.blade.php` "20+ Experiences / 10+ Communities" hardcoded; footer social links are `href="#"`; "Newsletter Section" comment but no signup form.
- `updateSpProfile` has zero validation (contrast traveller `updateProfile`).
- SP dashboard says "contact HCT to change bank details" but `/sp/profile/edit` lets the SP edit them directly — contradictory.
- `SpController::dashboard()` uses `->first()` with no null guard (`editProfile()` uses `firstOrFail()` — inconsistent).
- `submitSpApplication` accepts `services_offered/accommodation_categories/vehicle_types/activity_types` but not `guide_types`; the form sends none of these anyway.
- Calendar legend lists 5 statuses but only `confirmed`/`running` ever render; a trip spanning a whole month without starting/ending in it won't show.
- `region` country-filter not actually cascaded by the selected continent.
