================================================================
  HECO PORTAL — MVP BOOTSTRAP & OPERATIONAL FLOW
  Source-of-truth: MVP.pdf + current codebase (commit 16174d7)
  Written: 2026-05-14
================================================================

This doc describes how to bring up the HECO MVP from a COMPLETELY CLEAN
state — empty database, fresh checkout, no users, no data — and then
make it operational for real travellers + service providers.

Order matters. Skipping a step here usually means a 500 error somewhere
later (FK constraints, missing system_lists, missing AI prompts, etc.).

----------------------------------------------------------------
  PART A — TECHNICAL BOOTSTRAP (one-time, on a clean machine)
----------------------------------------------------------------

A.1  PREREQUISITES
  - Laravel Herd installed on Windows (provides PHP-FPM + MySQL + nginx)
  - PHP 8.2+ via Herd at:  C:\Users\<you>\.config\herd\bin\php.bat
  - Composer 2.x
  - Node 18+ / npm
  - MySQL 8 running (Herd starts it automatically)
  - Two Herd-configured local domains:
      hecoportal.test  → public/index.php
      hecoadmin.test   → public/index.php   (same codebase, domain-routed)
  - Optional but recommended for full functionality:
      Ollama running locally on http://localhost:11434  (AI fallback)

A.2  CODE + DEPENDENCIES
  1. git clone <repo> E:\heco
  2. cd E:\heco
  3. composer install
  4. npm install
  5. cp .env.example .env
  6. php artisan key:generate

A.3  .env CONFIGURATION (the minimum that must be set)

  # App
  APP_NAME="HECO Portal"
  APP_ENV=local
  APP_URL=http://hecoportal.test
  APP_DEBUG=true                   # set false in production

  # Database (Herd MySQL defaults)
  DB_CONNECTION=mysql
  DB_HOST=127.0.0.1
  DB_PORT=3306
  DB_DATABASE=hecoDB
  DB_USERNAME=root
  DB_PASSWORD=

  # Domain split — used by Route::domain() in routes/web.php
  PORTAL_DOMAIN=hecoportal.test
  ADMIN_DOMAIN=hecoadmin.test

  # Mail (use log driver until SMTP is configured; emails render to
  # storage/logs/ instead of being sent)
  MAIL_MAILER=log
  MAIL_FROM_ADDRESS=info@heco.eco
  MAIL_FROM_NAME="HECO Portal"

  # Cache / session / queue — all DB-driven by design
  CACHE_STORE=database
  SESSION_DRIVER=database
  QUEUE_CONNECTION=database

  # Logging (Rule 4: daily rotation)
  LOG_CHANNEL=daily

  # ===== AI providers (in fallback order) =====
  # Gemini — primary
  GEMINI_API_KEY=<your key>
  GEMINI_MODEL=gemini-2.5-flash
  GEMINI_TIMEOUT=60

  # Groq — secondary (fast llama)
  GROQ_API_KEY=<your key>
  GROQ_MODEL=llama-3.3-70b-versatile
  GROQ_TIMEOUT=60

  # Ollama — local fallback (free but slow; requires Ollama running)
  OLLAMA_HOST=http://localhost:11434
  OLLAMA_MODEL=mistral
  OLLAMA_TIMEOUT=120

  # ===== Razorpay (payments — sandbox keys for MVP) =====
  RAZORPAY_KEY_ID=<rzp_test_xxx>
  RAZORPAY_KEY_SECRET=<secret>

  # ===== OAuth (optional — Sign in with Google / Facebook) =====
  GOOGLE_CLIENT_ID=
  GOOGLE_CLIENT_SECRET=
  GOOGLE_REDIRECT_URI=http://hecoportal.test/auth/google/callback
  FACEBOOK_CLIENT_ID=
  FACEBOOK_CLIENT_SECRET=
  FACEBOOK_REDIRECT_URI=http://hecoportal.test/auth/facebook/callback

A.4  CREATE DATABASE
  1. Open Herd's MySQL CLI (or any client):
       CREATE DATABASE hecoDB CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  2. Verify:  php artisan db:show

A.5  RUN MIGRATIONS (create the schema)
       php artisan migrate

  This creates ~60 tables including users, trips, trip_days,
  trip_day_services, experiences, regions, service_providers,
  sp_availability, sp_pricing, leads, traveller_payments, sp_payments,
  ai_prompts, ai_conversations, activity_logs, system_lists, settings,
  currencies, regenerative_projects, pdf_templates, support_requests,
  password_reset_tokens, etc.

A.6  RUN SEEDERS  (REQUIRED ORDER — DatabaseSeeder enforces this)
       php artisan db:seed

  Order (do NOT change):
    1. AdminUserSeeder       — creates 3 baseline users:
                                 admin@hecoapp.com / password   (hct_admin)
                                 collaborator@hecoapp.com / password
                                 traveller@hecoapp.com / password
    2. RegionSeeder          — 20 regions across Asia/Africa/Europe/
                                 Oceania/South America (with anchor_points)
    3. SystemListSeeder      — 6 master lists:
                                 service_type / accommodation_category /
                                 vehicle_type / activity_type /
                                 experience_type / payment_mode
    4. PreferenceListsSeeder — 5 travel-pref lists whose NAMES MUST MATCH
                                 CostCalculatorService::getMultiplierMap()
                                 exactly (accommodation_comfort,
                                 vehicle_comfort, guide_preference,
                                 travel_pace, budget_sensitivity).
                                 If these labels drift from the multiplier
                                 map, pricing silently falls to 1.0.
    5. AiPromptSeeder        — DB-stored prompt templates (traveller_chat
                                 + others). The chat handler reads these
                                 at runtime, so missing = no AI.
    6. SettingSeeder         — gst_percent=5, default RP/HRP/HCT margins,
                                 base transport/accomm/guide costs, site
                                 name + email, AI defaults.
    7. CurrencySeeder        — USD, EUR, GBP, INR + others; rates_to_usd.
    8. TestDataSeeder        — OPTIONAL. Adds sample travellers, SPs,
                                 experiences, trips, RPs.
                                 SKIP this in production.

  For PRODUCTION-LIKE bootstrap (no fake data):
       php artisan db:seed --class=AdminUserSeeder
       php artisan db:seed --class=RegionSeeder
       php artisan db:seed --class=SystemListSeeder
       php artisan db:seed --class=PreferenceListsSeeder
       php artisan db:seed --class=AiPromptSeeder
       php artisan db:seed --class=SettingSeeder
       php artisan db:seed --class=CurrencySeeder

  For DEMO / test bootstrap (with fake trips, SPs, etc.):
       php artisan db:seed     # runs all 8 in order

A.7  BUILD FRONTEND ASSETS
       npm run build
  (Development: `npm run dev` for HMR.)

A.8  STORAGE & UPLOAD DIRECTORIES
       php artisan storage:link
       mkdir -p public\uploads\users
       mkdir -p public\uploads\experiences
       mkdir -p public\uploads\regenerative_projects
  (Year/month subfolders are auto-created by ImageUploadService on first
  upload — public/uploads/<type>/YYYY/MM/<uuid>.<ext>.)

A.9  RESTART HERD (flush OPcache)
       "C:\Users\<you>\.config\herd\bin\herd.bat" restart

A.10 VERIFY BOOTSTRAP
       curl -o NUL -w "%%{http_code}" http://hecoportal.test/    # 200
       curl -o NUL -w "%%{http_code}" http://hecoadmin.test/     # 302 → /login
       php artisan tinker --execute="echo App\Models\User::count();"
         # → 3   (admin / collaborator / traveller)
       php artisan tinker --execute="echo App\Models\Region::count();"
         # → 20
       php artisan tinker --execute="echo App\Models\SystemList::count();"
         # → ~60 entries across 11 list types
       php artisan tinker --execute="echo App\Models\Setting::count();"
         # → 11
       php artisan tinker --execute="echo App\Models\AiPrompt::count();"
         # → ~6

  Open http://hecoadmin.test/login → log in as admin@hecoapp.com / password.

----------------------------------------------------------------
  PART B — OPERATIONAL BOOTSTRAP (what the HCT admin does first)
----------------------------------------------------------------

After the technical bootstrap, the platform is wired but EMPTY of business
content. Here's the order in which the HCT admin makes it usable.

B.1  LOG IN AS ADMIN
  - hecoadmin.test/login → admin@hecoapp.com / password
  - First action: change your own password
        Control Panel → Profile & Access → change password
  - Optional: create additional HCT users
        Admin tab → HCT Users → Add HCT User
        (assign Admin or Collaborator role)

B.2  REVIEW SYSTEM SETTINGS
  Control Panel → Settings tab:
    - Confirm GST percent (default 5%)
    - Confirm default margins:
        default_rp_margin_percent       (5%)
        default_hrp_margin_percent     (10%)
        default_hct_commission_percent (15%)
    - Confirm base costs (transport_per_day, accommodation_per_night,
      guide_per_day) — these are the fallbacks the pricing engine uses
      when an experience doesn't define its own
    - Site name + site email

B.3  REVIEW SYSTEM LISTS (master dropdowns)
  Control Panel → System Lists tab. Audit each list type:
    - service_type, accommodation_category, vehicle_type, activity_type,
      experience_type, payment_mode
    - travel-preference lists (accommodation_comfort, vehicle_comfort,
      guide_preference, travel_pace, budget_sensitivity)
  Add / rename / deactivate entries to match your real operating set.
  ⚠️ DO NOT rename a travel-preference label without updating
  CostCalculatorService::getMultiplierMap() in code — pricing will break.

B.4  AI PROMPTS — REVIEW (and tune later)
  Control Panel → AI Prompts tab. Verify:
    - traveller_chat (the homepage AI advisor)
    - itinerary_generator (used by AI itinerary builder)
    - any others seeded
  These can be tuned at any time. Test changes via the chat.

B.5  REGIONS — POPULATE OPERATIONAL DETAILS
  /regions → for each region you'll actually operate in:
    - Verify anchor_points (Chandigarh, Bhuntar, etc.)
    - Confirm latitude/longitude (used on the homepage map)
    - Add external_url pointing to the matching page on
      himalayanecotourism.com (MVP §19 SEO continuity)
    - Toggle is_active = false for regions you're not yet serving
      (they'll be greyed on the map)

B.6  CURRENCIES — REVIEW RATES
  /currencies → confirm USD/INR/EUR/GBP rates_to_usd are reasonable.
  Update periodically.

B.7  CREATE REGENERATIVE PROJECTS (RPs)
  /regenerative-projects → Add New Project.
  Each operational region SHOULD have at least one active RP, OR
  fallback_for_regions populated so impact still renders.
    - Name, region, action_type (reforestation / fire-prevention / etc.)
    - Short description (traveller-facing) + detailed description
    - Impact unit + cost-per-unit + measurement frequency
    - Seasonality (active_periods / paused_periods)
    - Main image + gallery
  RPs are what the Impact tab on the homepage renders for each trip.

B.8  SERVICE PROVIDER ONBOARDING (HRP / HLH / OSP)
  Two paths — both valid in MVP:

  Path 1 — SP applies, HCT approves:
    1. SP visits hecoportal.test/join, fills the application form.
    2. SP receives SpApplicationReceivedEmail.
    3. HCT visits /provider-applications, reviews, clicks Approve.
    4. System auto-creates the linked User row (user_role = hrp/hlh/osp)
       and sends SpApplicationApprovedEmail with a set-password link.
    5. SP follows the link, sets a password, logs in at
       hecoportal.test/login → lands on /sp/dashboard.

  Path 2 — HCT enters SP directly (faster for known partners):
    1. /providers → Add Provider (or seed via tinker)
    2. Set status = approved
    3. Manually create the User row + send credentials offline
    (Path 1 is preferred — keeps a clean audit trail.)

  After approval, on /providers/<id>/edit:
    - Set SP pricing rows (service_type, category, rate, optional notes)
        — accommodation: per category × per occupancy (single/double/triple)
        - transport:    per km × per vehicle type
        - guide:        per day
        - activity:     per person / per group / per day
    These rates feed CostCalculatorService.

B.9  CREATE EXPERIENCES
  /experiences → Add Experience. For each:
    - Identification:
        Region (active region from B.5)
        HLH provider (approved SP whose provider_type='hlh')
        Type (Trek / Cultural Immersion / Nature / etc. from system_lists)
        Duration type (less_than_day / single_day / multi_day) + days/nights
    - Descriptions (short ≤500 chars, long unlimited)
    - Cost breakdown: cost_accommodation / cost_logistics / cost_guide /
      cost_activities / cost_other  → base_cost_per_person auto-summed
    - Constraints: min/max group, difficulty, age, fitness
    - Seasonality: available_months / restricted_months / unavailable_months
    - Inclusions (boolean flags: includes_accommodation / _transport /
      _guide / _activities / _meals + accommodation_category)
    - Day-wise details (experience_days table): per-day title + description
      + inclusions (overrides experience-level for that day)
    - Card image + gallery (year/month upload paths)
  Disable rather than delete experiences you no longer offer — they stay
  visible in historical trip records.

B.10 PDF TEMPLATES
  Control Panel → PDF Templates tab. One template seeded by default
  (itinerary_pdf). Customize header/footer/CSS if needed before HCT
  starts generating trip PDFs from Trip Manager.

----------------------------------------------------------------
  PART C — FIRST TRAVELLER FLOW (smoke-test after bootstrap)
----------------------------------------------------------------

C.1  GUEST DISCOVERY
  1. Open hecoportal.test/ (incognito browser).
  2. Landing page detects no session → invites soft preferences
     (region / style / dates / involvement).
  3. Lands on /home (Discover tab).
  4. Map shows active regions; experience cards listed.
  5. Filter by region/type/difficulty — only options that match real
     experiences should return rows.

C.2  ADD TO JOURNEY (still guest)
  6. Click an experience card → detail in new tab.
  7. "Add to Journey" → stored in session("guest_trip").
  8. Switch to Your Journey tab → see selected experience + auto-
     generated timeline + dynamic pricing.

C.3  SIGN UP / SIGN IN
  9. Click Save this trip → prompts sign up (or sign in if existing).
  10. After sign-up:
      - guest_trip syncs to a real Trip row (LeadService::createOrGetLead
        auto-creates a follow_up Lead).
      - traveller lands on /home with the trip loaded.

C.4  AI CHAT REFINEMENT
  11. Open the AI chat. Walk through name → preferences → dates →
      group size. AI emits TRIP_DETAILS tags; system persists to trip.
  12. AI can suggest adding/removing experiences — emits ADD_TO_TRIP /
      REMOVE_FROM_TRIP with VALIDATED ids (server drops fabricated ones).

C.5  CONFIRM TRIP
  13. Once at least one experience is selected and a region is set:
      Confirm Trip button becomes active.
  14. Click → trip.status flips from not_confirmed → confirmed.
  15. Server-side: LeadService::checkPaymentAndTransition only flips
      lead.stage to won when a real payment is recorded.

C.6  PAYMENT (manual MVP flow)
  16. HCT receives payment off-platform (UPI / bank / etc.).
  17. HCT opens Trip Manager for the trip:
      Trip Info → Add Payment (amount + date + mode).
  18. On first payment:
      - traveller status → Client
      - lead.stage → won (LeadService::markWon)
      - SP payment block auto-generated in Payments tab
      - Trip appears in Calendar + Upcoming Trips

C.7  IMPACT
  19. Your Impact tab shows the per-region RP card with computed units
      (trees / hectares / carbon) based on the trip's contribution share.

D.2  HCT reviews at /provider-applications → Approve.
D.3  SP receives email → clicks set-password link → sets password.

     Manager → Trip Itinerary → Day Services → Change SP), the SP

----------------------------------------------------------------
  PART E — DAILY OPS (HCT routines after launch)
----------------------------------------------------------------

E.1  MORNING (start of day):
  - Open HCT Dashboard / Home tab → review:
      Unresolved Support widget
      Upcoming Trips (30 days) widget
      Lead Reminders widget (Control Panel)
  - Action overdue follow-ups (Leads tab → reddish rows)

E.2  PER LEAD:
  - Open Trip Manager → Trip Info tab
  - Update last_interaction_date + interaction_mode + notes
  - Use AI chat or manual itinerary edits to converge the trip

E.3  PER PAYMENT:
  - Trip Manager → Trip Info → Add Payment
  - System auto-updates traveller status + trip status + lead stage

E.4  PER NEW SP APPLICATION:
  - /provider-applications → review + Approve/Reject/Request clarification

E.5  WEEKLY:
  - Review GST tab for last week's traveller payments
  - Verify SP payment blocks: any zero-balance trip blocks disappear
  - Audit Activity Logs (Control Panel → Activity Logs tab)
  - Review iCal sync errors (storage/logs/laravel-YYYY-MM-DD.log)

E.6  MONTHLY:
  - GST report → export for filing
  - Update currency rates (/currencies → edit rate_to_usd)
  - Review impact reports

----------------------------------------------------------------
  PART F — RESETTING THE DB (if you ever need to start over)
----------------------------------------------------------------

  ⚠️ DESTRUCTIVE — wipes everything.

  php artisan migrate:fresh --seed

  Then repeat Part B (operational bootstrap). The 8 seeders in Part A.6
  give you a working tech baseline; Part B turns it into a real platform.

  To wipe ONLY transactional data but keep regions/system_lists/etc.:
      Use tinker:
        Trip::query()->delete();
        Lead::query()->delete();
        TravellerPayment::query()->delete();
        SpPayment::query()->delete();
        SpAvailability::query()->delete();
        AiConversation::query()->delete();
        TripSelectedExperience::query()->delete();
        TripDay::query()->delete();
        TripDayService::query()->delete();
        TripDayExperience::query()->delete();
        TripRegion::query()->delete();
        User::where('user_role','traveller')->delete();   # test travellers only

----------------------------------------------------------------
  PART G — COMMON PITFALLS (learned the hard way)
----------------------------------------------------------------

  1. OPcache: Herd's PHP-FPM caches PHP files. After changing
     controllers, routes, or .env values, run:
       "C:\Users\<you>\.config\herd\bin\herd.bat" restart
     (artisan optimize:clear is NOT sufficient — that clears the CLI
     cache, not the PHP-FPM one.)

  2. ConvertEmptyStringsToNull middleware: empty querystring params
     (?status=) arrive as null, not "". Filter handlers must check
     !empty($x), not $x !== "" — the latter is TRUE for null.

  3. Single-region rule: a trip can only span ONE region. Don't seed
     experiences from multiple regions into the same trip.

  4. Travel preference labels are MAGIC STRINGS that the pricing engine
     match()es against. Don't rename them in system_lists without
     updating CostCalculatorService::getMultiplierMap().

  5. service_providers.services_offered stores TITLE-CASE labels
     ("Transport", "Accommodation"), trip service_type columns store
     LOWERCASE singular ("transport"). The mapping is in
     SpMatchingService::serviceOfferedLabel — don't bypass it.

  6. trip_id in URLs is the integer primary key (1, 2, ...), NOT the
     trip code (HECO-T-0103). Use $trip->id not $trip->trip_id when
     building admin links.

  7. CSRF token rotates on login/session-regen. After login, re-fetch
     the meta-tag from any subsequent GET before posting AJAX.

  8. UTF-8: if the AI provider throws "Malformed UTF-8", the prompt
     template or user message has a bad byte. mb_check_encoding the
     stored prompt and any region/user input.

  9. SP dashboard requires SP.status === 'approved'. SpMiddleware AND
     resolveApprovedSp() helper both enforce this — keep both in sync.

  10. Daily log channel: storage/logs/laravel-YYYY-MM-DD.log rotates
      automatically. Don't write a single growing laravel.log.
