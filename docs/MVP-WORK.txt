     Currently only `subscribe_newsletter` writes to `activity_logs`. Every
     other admin action skips it. Doc wants reliable retrieval of records.
     ~2-3 hours (one shared helper called from every save/update/delete).

  4. AI ↔ HCT chat-style data-feeding interface (MVP §12.5 C)
     Today HCT support requests + Trip Manager edits cover the same ground
     pragmatically. Doc envisages a dedicated chat. Decide whether to build
     it or accept the existing pattern as MVP-sufficient.

  5. Portal-side PDF download (`/pdf/trip/{id}`)
     Route only on admin domain. Travellers can't download their own
     itinerary PDF. Doc doesn't explicitly require it. Confirm intent.

       in prod by APP_DEBUG=false.

       env('local')-gated.
